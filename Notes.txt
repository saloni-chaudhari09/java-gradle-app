18. PROBLEM WE FACED: NO MAIN MANIFEST ATTRIBUTE
============================================================

Initially, when we ran:

java -jar build/libs/java-gradle-app-1.0.jar


We received:

no main manifest attribute


REASON:

The JAR did not contain information about which Java class should be
executed first.


SOLUTION:

We added the following to build.gradle:

jar {
    manifest {
        attributes(
            'Main-Class': 'com.example.App'
        )
    }
}


Then we ran:

gradle clean build


After rebuilding, the JAR could be executed using:

java -jar build/libs/java-gradle-app-1.0.jar

============================================================

We also faced a Gradle Java toolchain problem.

Gradle displayed:

Toolchain installation does not provide the required capabilities:
[JAVA_COMPILER]


The important issue was that Gradle detected the Java installation as:

Is JDK: false


But javac was actually available.


We checked Java:

java -version


We checked Java compiler:

javac -version


Output:

javac 21.0.12.1


We checked Java location:

which java


We checked compiler location:

which javac


We also checked Gradle Java toolchains:

gradle -q javaToolchains


Gradle initially detected:

Amazon Corretto JRE 21

Is JDK: false


The problem was Gradle's toolchain/daemon detection.


We stopped the Gradle daemon:

gradle --stop


After correcting the Java environment and restarting Gradle,
the build succeeded.

1. Check java -version

7. Restart Gradle daemon using gradle --stop

============================================================
35. DEPLOY STAGE
============================================================

Our deployment stage:

stage('Deploy') {
    steps {
        sh '''
            mkdir -p /opt/java-gradle-app/deploy

            cp build/libs/*.jar /opt/java-gradle-app/deploy/app.jar

            pkill -f 'java -jar /opt/java-gradle-app/deploy/app.jar' || true

            nohup java -jar /opt/java-gradle-app/deploy/app.jar \
                > /opt/java-gradle-app/deploy/app.log 2>&1 &
        '''
    }
}


What happens:

First the deployment directory is created.

Then the generated JAR is copied:

build/libs/*.jar

to:

/opt/java-gradle-app/deploy/app.jar


If an older application process is running, it is stopped.

Then the new JAR is started.

Application log is written to:

/opt/java-gradle-app/deploy/app.log
